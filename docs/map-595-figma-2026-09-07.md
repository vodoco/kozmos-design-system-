drawn on the current level — it _is_ the container you are browsing. Its result appears in the

| **List header**    | Things that change what you are browsing — **Building**, **Level**           |

A building is a _place you go_; a POI is a _thing you put there_. Different levels of the hierarchy,

# Session 18 — Adjust, in the prototype only

## 66 · Reshape + Transform are one tool

`mode: "adjust"` renders **both** handle sets: the outline's own corners and midpoints, and the
transform box with its scale corners and rotate knob. It is the default mode a selection opens in,
and it is what a cut or a reset returns to.

The toolbar's two tiles became one — **Adjust**.

**Why not "Edit":** you already pressed Edit to get here, so a tile of that name reads as a button
that does nothing. Same objection kills "Select" — you already selected. "Adjust" names what
separates this tile from its neighbours: Split, Cut-out, Combine, Straighten and Simplify all
**compute** a result; this is the one you do **by hand**.

## 67 · The code's own objection was real, and it needed a number

The map page carried a note saying the box is _"not shown in Reshape, where the corners of the
outline are the subject and a second set of squares nearby would be a coin toss every time you
reached for one."_ That was not stale caution — at `BOX_PAD = 12` it is arithmetically true:

- on a rectangle the box corner sits **12·√2 ≈ 17px** from the vertex it shadows
- a vertex is a **r5 circle**, a scale corner a **9px square**
- so the clear air between them is **17 − 5 − 4.5 ≈ 7.5px**

Adjust therefore pushes the box out to **`BOX_PAD_ADJUST = 18`**, giving ~25px between centres and
**~16px of clear air** — far enough that position separates them as well as shape does. The two sets
were already a circle and a square; they are now also apart.

# Session 21 — GEOM holds N features, and transform-all

## 77 · The change

`GEOM.also` — the rest of the selection as `{ fid, rings }`, resolved map-side on `begin` because the
app has never held these rings. `MapContent` now sends `alsoFids` with the begin command.

The transform seam turned out to be **three lines**. `fromOrigin(fn)` is a coordinate mapping applied
to the primary's rings; extending it to the others makes move, scale and rotate act on the whole
selection for free:

```js
const fromOrigin = (fn) => {
  GEOM.rings = origRings.map((r) => r.map(fn));
  if (origPoint) GEOM.point = fn(origPoint);
  for (let i = 0; i < origAlso.length; i++)
    GEOM.also[i].rings = origAlso[i].rings.map((r) => r.map(fn));
};
```

`geomBox()` now spans the union, so the box is around the **selection** and rotation is about **its**
centre — which is what US4 asks for. The dominant-angle calculation reads all of them too, so the box
sits on the group's grid rather than the primary's.

Also carried: `geomSnap`/`geomRestore` include `also` (an undo that put the primary back and left the
others moved would be worse than no undo), and both commit paths report every feature that moved.

The other features draw as lighter outlines with `pointer-events: none` — **their corners are not
handles this pass.** The selection keys are `"ri:ci"` and carry no feature index, so a second

# Session 22 — adjust all selected nodes

> _"now do the vertex keys so I can adjust all selected nodes"_ — Olcay, 2026-09-08

## 80 · The key grew a feature index

`"ri:ci"` → **`"fi:ri:ci"`**. `fi` is the feature's position in the selection: `0` is the primary —
the one the panel is on — and `1..n` index `GEOM.also`.

That one change is the whole feature. Without it a corner of the second room and a corner of the
first were literally the same key, so selecting one lit up both and dragging one tore them apart;
with it, every path that already handled "several corners at once" handles "several corners across
several features" without knowing it has.

```js
const selKey = (fi, ri, ci) => fi + ":" + ri + ":" + ci;
const parseKey = k => k.split(":").map(Number);
/** Every selected feature's rings, primary first — the array `fi` indexes into. */
function geomAllRings() {
  return [GEOM.rings || []].concat((GEOM.also || []).map(a => a.rings));
}
/** One feature's live rings by index. */
function geomRingsAt(fi) { ... }
```

⚠️ **A network keeps putting node `fid`s in the same `GEOM.sel` Set.** Two key spaces in one Set,
which is fine only because nothing parses a key without having checked `GEOM.kind` first. Written
down at the declaration so the next person does not have to rediscover it.

### What moved with it

| Path                      | Before                                                                   | Now                                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Draw                      | primary's faces + handles; others a light outline, `pointer-events:none` | faces for **all**, then handles for **all** — two passes, so a handle is never buried under the next feature's fill |

## 88 · 🔴 Two defects, both mine, both live until now

Making `GEOM.also` follow the selection (§81, fix 2) was necessary — without it transform-all did
nothing for the normal gesture order, because `begin` is only re-sent when the _primary_ changes, so
shift-clicking a second feature never reached the editor. But it had two consequences I did not
follow through, and **both were confirmed against the deployed page before being touched**:

**1 · Adding a feature to the selection announced unsaved changes.**

```
dirtyAtOpen:                    false
dirty_after_ADDING_a_feature:   true      ← nobody edited anything
dirty_after_REMOVING_it_again:  false     ← which is why it never got noticed
```

`dirty` is `geomSnap()` against `GEOM.original`, and both carry `also`. Changing the membership
changed the comparison. Not cosmetic: it lights up Cancel and Update, and US2's guard then blocks
the next selection over an edit that does not exist. It round-trips, which is exactly why a casual
click-about would not find it.

**Fixed** by re-basing `GEOM.original.also` in `geomSetSelection` — a member that was already there
keeps the baseline it had, edits and all; one that has just joined takes its current outline,
because that is what unedited means for it. Joining a selection is not an edit.

**2 · Undo resurrected a feature the app had deselected.**

`geomRestore` put `s.also` back wholesale, so a feature shift-clicked OUT of the selection returned
to the map — with corner handles on it, since §80 — while the panel went on saying one feature was
selected. A drag then moved geometry nothing would ever commit.

**Fixed** by restoring geometry **by fid onto the current membership**. Who is selected belongs to
the app; this history is about shape. A member the snapshot never saw goes back to its own baseline
instead, which is the outline it joined with.

**And a third thing, which was not a bug but was silent.** A member taken back out of the selection
takes its unsaved shape changes with it — there is nowhere for the edit to live once the panel is
not on it, and Save commits only what the editor holds, so discarding it is right. Discarding it
without a word is not. It now says so, and only when something was actually changed.

# Session 30 — the six controls, designed

> _"design the six controls"_ — Olcay, 2026-09-09

## 114 · ⑤ · "The six controls the taxonomy leaves to us" (`486:1532`, y 15280)

Each is built **from Core parts** — the same 8px box, the same 1px border, the same type — so a panel
made of them reads as one form rather than as six inventions. Nothing here changes a Core component.

⚠️ **The constraints are read, not typed.** The taxonomy publishes them, and reading them is the
difference between a control that stays true and one that drifts:

| control        | what the taxonomy gives                         | what that decides                                                        |
| -------------- | ----------------------------------------------- | ------------------------------------------------------------------------ |
| `description`  | `maxLength: 10000`                              | the counter is real, and its overflow state has a number to fail against |
| `priceRange`   | `validation: min 1, max 4`                      | **four steps** — not a dropdown, not a number field                      |
| `images`       | `maxItems / maxCount: 7`                        | the `n / 7` counter, and a disabled add at the cap                       |
| `logo`         | `restriction: "* Max 1MB \| JPG & PNG \| 1:1"`  | the caption **verbatim**, and a square thumbnail                         |
| `images`       | `restriction: "* Max 2MB \| JPG & PNG \| 16:9"` | a 16:9 thumbnail                                                         |
| `rating`       | `display.highlight: 10`                         | it is lifted into the POI card's highlight band                          |
| `openingHours` | **nothing but `object`**                        | the shape is ours — see below                                            |

## 115 · What each one decides

**1 · Textarea** — the taxonomy's only `textArea`, and the one control Core has no component for.
Identical chrome to Text-Inputs; the differences are that the value wraps, the box has a minimum
height, and the count is shown. Drawn in Default, Filled and Error. ⚠️ The counter uses the DS's own
`Input/Character-limit` text style — **Core anticipated this control and never shipped it**.

**2 · Opening Hours** — ⚠️ **the taxonomy publishes no schema at all**, so the shape is a product
decision and should be made deliberately rather than copied. The running product draws seven rows of
two time fields and stops. Three things it cannot say, all of which a venue needs: that a day is
**closed**, that a day runs 24 hours, and that the other six days are **the same as this one**. A
schedule you cannot close on a Sunday is not a schedule. So: a per-day Open toggle (Core's, Small,
own label off — the day name is the label), and _Copy Monday to all days_. A closed day **keeps its
row** and loses its time fields, because the row is where you go to re-open it.

**3 · Logo** — empty state is an upload target, not an empty field: a URL box tells you nothing about
what it wants. The thumbnail is **square because the restriction says 1:1** — an image control that
does not show the aspect it demands lets you upload the wrong thing and find out later.

**4 · Images** — the count is derived from the cap, and at 7 / 7 the add is **disabled and says why**.
A disabled control with no reason is the commonest way a form stops being usable.

**5 · Price band** — four steps, composed from Core's Button-Group, clearable because the property is
optional. A dropdown would hide the range; a number field would invite 7.

**6 · Rating** — three numbers that mean nothing apart (a 4.6 with no maximum is not a rating), so one
bordered group and one delete, not three properties. Under it, the control reads itself back —
_"4.6 out of 5, from 321 ratings"_ — which is also exactly what the POI card will print.

**How "greyed" is drawn, and why not the obvious way**
