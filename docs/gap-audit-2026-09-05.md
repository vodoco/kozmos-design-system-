# Gap Audit, 2026-09-05

What the design system is missing, measured rather than remembered.

Three sources: the **POI Details Card Revamp** Figma file
(`HbFSXhCPxKUy2fWa5x9TKO`, three nodes the user named), the **Kozmos Core
Library** (`Yj4O8p6Y9h2Sa9zJVoAiVY`) read over REST, and the monorepo itself.
Every count below came from a listing or a measurement. Where an earlier
document disagrees, the earlier document is wrong and is named.

## The headline

Component **presence** is not the problem. React, iOS and Android each carry
**97** components and their name sets are byte-identical, verified by listing.
The problems are in four other places:

1. **Three components have never been built in Figma** — and that silently
   explains a Code Connect gap on all three platforms.
2. **The library sits off its own type scale** — 95% of its text.
3. **The revamp designs need about twenty patterns the library does not have**,
   concentrated in POI detail and wayfinding.
4. **Six native components are thin wrappers** around an OS control, not
   implementations of the Kozmos component.

---

## 1. Text, Heading and Label do not exist in Figma

The strongest finding, because it explains a second one.

`CORE_UPDATE_SEQUENCE` and `PRODUCT_SDK_UPDATE_SEQUENCE` name **97** sets. The
Components page holds **94**. The three missing are **Text**, **Heading** and
**Label**.

All three have builders in `code.js`, all three are selectable in the plugin's
dropdown, and none has ever been run. `Update All Core` reports them as "not
present and skipped" on every pass, which is why nobody noticed.

The consequence: those same three are the only components with a Figma set in
the sequence and **no Code Connect file on React, iOS or Android**. A previous
audit read that as deliberate, since they are primitives. It is not deliberate
— there is no node to connect to.

**To do**

- Build Text, Heading and Label from the plugin's dropdown, then verify the page
  reads 97.
- Add `Text.figma.tsx`, `Heading.figma.tsx`, `Label.figma.tsx` and the Swift and
  Kotlin equivalents. That is 9 files.

## 2. The library is 95% off its own font scale

`Primitives.Typography.font.size` runs 8, 10, 11, 13, 16, 20, 24, 30, 38, 48 and
upward. The Figma library's 6,797 text nodes use:

| size | uses | on the scale |
| ---- | ---- | ------------ |
| 14   | 6087 | no           |
| 12   | 376  | no           |
| 11   | 292  | yes          |
| 24   | 29   | yes          |
| 18   | 10   | no           |
| 16   | 3    | yes          |

**324 of 6797, or 5%.** The workhorse size, 14, is not a step on the scale at
all. This is the "font sizes are untokenised" item that has been in the handoff
for a week, now quantified: it is not a few strays, it is the whole library.

Two steps also carry floating-point noise and should be integers:

```
Primitives.Typography.font.size.100 = 11.008000373840332   → 11
Primitives.Typography.font.size.200 = 13.008000373840332   → 13
```

Worth noting for the decision below: **the revamp designs are closer to the
token scale than the library is.** They lean on 11 and 13, which are real steps;
the library leans on 14 and 12, which are not.

**To do** — one decision, then a sweep:

- Decide whether 14 and 12 join the scale, or the library moves to 13 and 11.
  Every other number follows from that.
- Clean the two noisy steps regardless; they are unambiguous.
- Then a parity check in the shape of `tokens:radius:check`, so text cannot
  drift off the scale again.

## 4. The icon library is too small

**38 icons.** The three designs reference a substantially larger vocabulary
that is not in it, including: eye, feather, clock-plus, bookmark, heart, help,
filter, images, loading, caret-up-small, caret-down-small, arrow-right,
facility/accessibility-services, and the 33 transition symbols above.

**To do** — inventory the designs' icon usage properly, then extend the set.
This blocks several of the components in section 3, since they are mostly icon
plus text.

## 5. Native components that are wrappers, not implementations

Presence parity is exact, but depth is not. Measured in implementation lines,
excluding Code Connect files:

| Component    | React | iOS    | Android | Note                                                                            |
| ------------ | ----- | ------ | ------- | ------------------------------------------------------------------------------- |
| `Slider`     | 194   | **21** | 34      | SwiftUI `Slider` with value and range only. No size, variant, disabled or marks |
| `DatePicker` | 321   | **20** | 70      | SwiftUI `DatePicker` with `.labelsHidden()`. No variants                        |
| `TimePicker` | 124   | **20** | 62      | Same shape                                                                      |
| `FileUpload` | 313   | 67     | 111     | Substantially reduced surface                                                   |
| `Select`     | 189   | 46     | 52      | Reduced                                                                         |
| `Breadcrumb` | 113   | 34     | 55      | Moderate                                                                        |

`Grid`, `Text`, `Spinner` and `Skeleton` are also thin, and that is correct —
they are primitives the platform already provides.

Three apparent gaps were measurement artefacts and are **not** defects:
`DateRangePicker` is a React re-export, `IconButton` delegates to `Button`, and
`Skeleton` really is one element.

## 6. Test coverage is nominally complete and actually thin

| Artefact                         | Have  | Of 97  |
| -------------------------------- | ----- | ------ |
| Storybook story                  | 97    | 100%   |
| Unit test                        | 97    | 100%   |
| MDX doc                          | 97    | 100%   |
| Code Connect (React)             | 92    | 95%    |
| **Any automated a11y assertion** | **5** | **5%** |

The 100% is soft. **29 of 97 test files hold one or two assertions** — a smoke
test that the component renders. The whole suite is 550 assertions across 97
files, a median of about four.

There is **no coverage threshold anywhere** in the repo. `vitest.config.ts`
configures a coverage reporter and no `thresholds` key, and no other config sets
one. So the thin tests cannot fail anything.

`vitest-axe` is installed and wired into the shared test setup, and only
`Tooltip` uses it. A separate central spec covers `Button`, `IconButton`, `Card`
and `Input`. That is the whole of the accessibility automation.

**To do**

- Set a coverage threshold, even a low one, so it can only go up.
- Extend the a11y spec to cover the interactive components rather than four.
- Deepen the 29 smoke tests, starting with the ones that carry real behaviour:
  `Dialog`, `Menu`, `BottomSheet`, `Toast`, `Pagination`, `Search`.

## 7. Smaller things worth recording

- **`Icon` is Code Connected to a node the importer does not maintain.** The pin
  resolves — node `15:2` is a component called "Icon / Slot Default" — but no
  builder regenerates it, so it can drift with nothing to catch it.
- **`@kozmos/vue` runs React at runtime.** There are zero `.vue` files. The
  package exports 101 `createVueWrapper(...)` bindings and mounts React DOM roots
  inside Vue nodes, so it carries `react-dom` as a runtime dependency. It is
  version `0.0.1` and appears in no release config. This is an architectural
  decision that is not written down anywhere.
- **The two 97s are not the same 97.** Four Figma names have no React directory
  — `FormField` (the code calls it `FieldWrapper` and re-exports the Figma
  name) and `TreeItem`, `TreeChildItem`, `TreeParentItem` (Figma decomposes
  what the code composes in one `Tree.tsx`). Four React directories are in no
  Figma sequence: `FieldWrapper`, `Icon`, `NavigationAnnouncer` and
  `ThemeProvider`. The last two are non-visual and correctly absent. The counts
  coinciding at 97 is a coincidence worth not reading anything into.
- Two orphaned Figma variables from the 2026-09-04 rename:
  `NavigationItem/padding/x` and `NavigationItem/gap`. They bind nothing.

## Suggested order

Cheap and unblocking first.

1. **Build Text, Heading, Label** and add their nine Code Connect files. An
   hour, closes two findings at once.
2. **Fix the two noisy font tokens.** Minutes.
3. **Decide the type scale question** in section 2. Everything typographic waits
   on this, and it is one decision.
4. **Set a coverage threshold** and widen the a11y spec. Half a day, and it stops
   the erosion.
5. **Extend the icon set** to cover the revamp designs. Blocks section 3.
6. **Build the POI attribute section**, the single highest-value component in
   the designs. Then the meta strip and opening hours.
7. **Deepen the six native wrappers**, `Slider` first, since it is the furthest
   from its React counterpart.
8. **The wayfinding family** — directions card, journey progress, checkpoints —
   as one piece of work, since they share a visual language.
