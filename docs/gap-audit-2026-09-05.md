# Gap Audit, 2026-09-05

What the design system is missing, measured rather than remembered.

Three sources: the **POI Details Card Revamp** Figma file
(`HbFSXhCPxKUy2fWa5x9TKO`, three nodes the user named), the **Kozmos Core
Library** (`Yj4O8p6Y9h2Sa9zJVoAiVY`) read over REST, and the monorepo itself.
Every count below came from a listing or a measurement. Where an earlier
document disagrees, the earlier document is wrong and is named.

## The headline

Component **presence** is not the problem. React, iOS and Android each carry
**97** components and their name sets are byte-identical, verified by listing.
The problems are in five other places:

1. **Three components have never been built in Figma** — and that silently
   explains a Code Connect gap on all three platforms.
2. **The library sits off its own type scale** — 95% of its text.
3. **The revamp designs need about twenty patterns the library does not have**,
   concentrated in POI detail and wayfinding.
4. **The SDK lane and its React implementation model different anatomies.** The
   biggest body of work here, and mostly design decisions before code. One
   component was visibly broken in the published library.
5. **Six native components are thin wrappers** around an OS control, not
   implementations of the Kozmos component.

**Two things were fixed while writing this**, both mechanical and neither a
judgement call: `UserLocationMarker`'s three shapes were rendering as a vertical
stack outside their frame, and four Code Connect files imported the same
identifier twice. Everything else is left as a note, as asked.

## 1. Text, Heading and Label do not exist in Figma

The strongest finding, because it explains a second one.

`CORE_UPDATE_SEQUENCE` and `PRODUCT_SDK_UPDATE_SEQUENCE` name **97** sets. The
Components page holds **94**. The three missing are **Text**, **Heading** and
**Label**.

All three have builders in `code.js`, all three are selectable in the plugin's
dropdown, and none has ever been run. `Update All Core` reports them as "not
present and skipped" on every pass, which is why nobody noticed.

The consequence: those same three are the only components with a Figma set in
the sequence and **no Code Connect file on React, iOS or Android**. A previous
audit read that as deliberate, since they are primitives. It is not deliberate
— there is no node to connect to.

All three builders are complete and their axis constants are defined, so this
is a Build away, not a build. The cost:

| set     | axes                          | variants |
| ------- | ----------------------------- | -------- |
| Text    | 8 sizes × 4 weights × 4 tones | **128**  |
| Heading | 6 levels                      | 6        |
| Label   | 2 states                      | 2        |

128 is large but not unusual here — TreeItem is 216 and ColorPicker 96.

**To do**

- Build Text, Heading and Label from the plugin's dropdown. Use **Build**, not
  Update: these sets do not exist yet, which is the one case Build is for.
  Then confirm the page reads 97.
- Add `Text.figma.tsx`, `Heading.figma.tsx`, `Label.figma.tsx` and the Swift and
  Kotlin equivalents. That is 9 files.
- Re-run `pnpm figma:verify`; the presence check expects 94 today and will need
  its expected count moved to 97.

## 2. The library is 95% off its own font scale

`Primitives.Typography.font.size` runs 8, 10, 11, 13, 16, 20, 24, 30, 38, 48 and
upward. The Figma library's 6,797 text nodes use:

| size | uses | on the scale |
| ---- | ---- | ------------ |
| 14   | 6087 | no           |
| 12   | 376  | no           |
| 11   | 292  | yes          |
| 24   | 29   | yes          |
| 18   | 10   | no           |
| 16   | 3    | yes          |

**324 of 6797, or 5%.** The workhorse size, 14, is not a step on the scale at
all. This is the "font sizes are untokenised" item that has been in the handoff
for a week, now quantified: it is not a few strays, it is the whole library.

Two steps also carry floating-point noise and should be integers:

```
Primitives.Typography.font.size.100 = 11.008000373840332   → 11
Primitives.Typography.font.size.200 = 13.008000373840332   → 13
```

Worth noting for the decision below: **the revamp designs are closer to the
token scale than the library is.** They lean on 11 and 13, which are real steps;
the library leans on 14 and 12, which are not.

**To do** — one decision, then a sweep:

- Decide whether 14 and 12 join the scale, or the library moves to 13 and 11.
  Every other number follows from that.
- Clean the two noisy steps regardless; they are unambiguous.
- Then a parity check in the shape of `tokens:radius:check`, so text cannot
  drift off the scale again.

## 5. The SDK lane has drifted from its React implementation

This is the largest body of work in the audit, and it is what the user meant by
"big differences in the SDK components". All 24 Product/SDK sets have a React
implementation and a Code Connect file, so nothing is missing. What has happened
is that **the two sides have been modelling different anatomies**.

The mechanism is visible in the history. Since 2026-08-29 the importer took **39**
commits and `packages/react/src/components/` took **11**, none of them touching an
SDK component — those files last changed on 2026-08-28, in a single commit. The
Figma side has been evolving alone for a week. Token parity all passes, so this is structural
drift, not token drift.

Across the lane: 24 Figma axes, about 149 React props, and about **59 Code
Connect bindings — roughly 40%**. The repo's own `components:variant:check`
already prints "Figma axes with no React prop" for **17 of the 24**.

### Fixed during this audit

- **`UserLocationMarker` was visibly broken in the published library.** The
  builder set `.x`/`.y` on the accuracy halo, heading cone and location dot
  without opting them out of the parent's auto-layout, so the coordinates were
  ignored and three concentric shapes rendered as a vertical stack — the halo at
  y −22 and the dot at y 66 in a 64px frame, both outside it. Confirmed live in
  both variants before fixing. A `placeAbsolute()` helper now does what the
  other five absolute children in the file already did. **Needs an Update of
  UserLocationMarker to take effect.**
- **Four Code Connect files imported the same identifier twice**, from
  `../X/X` and `./X`: `MapControlsGroup`, `MapOverlay`, `POIDetailPanel`,
  `RouteSummary`. Removed.

### Still open, cheap

- **Code Connect files are excluded from typecheck.**
  `packages/react/tsconfig.json` lists `src/**/*.figma.tsx` under `exclude`,
  so `pnpm typecheck` never sees a single one, while `figma.config.json` does
  feed them to the Code Connect parser. That exclusion is why the duplicate
  imports survived.

  Lifting it and running the package's own `tsc` gives **57 errors across 20
  files, and all 20 are SDK components** — no Core file errors at all. **53 of
  the 57 are `TS2304`, "cannot find name"**: examples referencing identifiers
  that are never imported or defined, such as `poi`, `options`, `zoomIn`,
  `floors` and `deviceHeading`. The baseline with the exclusion in place is
  clean, so none of this is visible today. Removing the exclusion closes the
  class permanently but surfaces those 20 files first.

### Still open, and each one is a design decision first

### A radius hole the parity check cannot see

Four React components reach **past** the semantic roles into a primitive:
`RouteSummary`, `RoutingInputGroup`, `SaveLocationCard` and `FeedbackCard` all
use `rounded-[var(--primitives-radius-2xl)]`, which is 32px, where the container
role is 20. `tokens:radius:check` passes because it verifies that the roles
agree across plugin, Tailwind and native; it does not look for components
bypassing the roles. **Worth extending** — it is the same class of defect the
border parity check was built for.

Four more use `control` (16) in Figma and `rounded-container` (20) in React.

## 7. Test coverage is nominally complete and actually thin

| Artefact                         | Have  | Of 97  |
| -------------------------------- | ----- | ------ |
| Storybook story                  | 97    | 100%   |
| Unit test                        | 97    | 100%   |
| MDX doc                          | 97    | 100%   |
| Code Connect (React)             | 92    | 95%    |
| **Any automated a11y assertion** | **5** | **5%** |

The 100% is soft. **29 of 97 test files hold one or two assertions** — a smoke
test that the component renders. The whole suite is 550 assertions across 97
files, a median of about four.

There is **no coverage threshold anywhere** in the repo. `vitest.config.ts`
configures a coverage reporter and no `thresholds` key, and no other config sets
one. So the thin tests cannot fail anything.

`vitest-axe` is installed and wired into the shared test setup, and only
`Tooltip` uses it. A separate central spec covers `Button`, `IconButton`, `Card`
and `Input`. That is the whole of the accessibility automation.

**To do**

- Set a coverage threshold, even a low one, so it can only go up.
- Extend the a11y spec to cover the interactive components rather than four.
- Deepen the 29 smoke tests, starting with the ones that carry real behaviour:
  `Dialog`, `Menu`, `BottomSheet`, `Toast`, `Pagination`, `Search`.

## 8. Smaller things worth recording

- **`Icon` is Code Connected to a node the importer does not maintain.** The pin
  resolves — node `15:2` is a component called "Icon / Slot Default" — but no
  builder regenerates it, so it can drift with nothing to catch it.
- **`@kozmos/vue` runs React at runtime.** There are zero `.vue` files. The
  package exports 101 `createVueWrapper(...)` bindings and mounts React DOM roots
  inside Vue nodes, so it carries `react-dom` as a runtime dependency. It is
  version `0.0.1` and appears in no release config. This is an architectural
  decision that is not written down anywhere.
- **The two 97s are not the same 97.** Four Figma names have no React directory
  — `FormField` (the code calls it `FieldWrapper` and re-exports the Figma
  name) and `TreeItem`, `TreeChildItem`, `TreeParentItem` (Figma decomposes
  what the code composes in one `Tree.tsx`). Four React directories are in no
  Figma sequence: `FieldWrapper`, `Icon`, `NavigationAnnouncer` and
  `ThemeProvider`. The last two are non-visual and correctly absent. The counts
  coinciding at 97 is a coincidence worth not reading anything into.
- **The overflow check was improved during this audit** and now measures both
  axes and ignores absolutely positioned children. Height matters because the
  file-row defect fixed on 2026-09-04 was a height overflow that a width-only
  rule could not see. Absolute children are excluded because they have opted
  out of the parent's layout — 913 nodes in the file are absolute, 901 of them
  focus rings, which are deliberately larger than the thing they ring. The rule
  now reports **5**: the two accepted button labels, plus three `DynamicIsland`
  slots that are 2px taller than their content box, which corroborates the
  geometry disagreement recorded in section 5.
- Two orphaned Figma variables from the 2026-09-04 rename:
  `NavigationItem/padding/x` and `NavigationItem/gap`. They bind nothing.

## Suggested order

Cheap and unblocking first.

1. **Update `UserLocationMarker`** in the plugin. The fix is committed; the
   published library still shows the broken marker until it runs. Minutes.
2. **Build Text, Heading, Label** and add their nine Code Connect files. An
   hour, closes two findings at once.
3. **Fix the two noisy font tokens.** Minutes.
4. **Stop excluding `*.figma.tsx` from typecheck**, then work through the 21
   files it surfaces. That permanently closes a class that has been invisible.
5. **Decide the type scale question** in section 2. Everything typographic waits
   on this, and it is one decision.
6. **Settle `POIDetailPanel`'s action set**, since "Save" is not in the
   contract at all. That unblocks the rest of the SDK list, which is a series of
   the same kind of decision.
7. **Set a coverage threshold** and widen the a11y spec. Half a day, and it stops
   the erosion.
8. **Extend `tokens:radius:check`** to flag components reaching past the roles
   into a primitive. Four do today.
9. **Extend the icon set** to cover the revamp designs. Blocks section 3.
10. **Build the POI attribute section**, the single highest-value component in
    the designs. Then the meta strip and opening hours.
11. **Deepen the six native wrappers**, `Slider` first, since it is the furthest
    from its React counterpart.
12. **The wayfinding family** — directions card, journey progress, checkpoints —
    as one piece of work, since they share a visual language.
